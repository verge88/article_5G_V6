# Open5GS/UERANSIM experiment for 5G KIE evidence verification

This directory implements the experimental plan from the research specification: the measured profile is **Nsmf_PDUSession CreateSMContext** at one AMF-to-SMF/SCP boundary. The unit of account is an individual service-call attempt. HTTP/2 `(connection epoch, stream ID)` is retained so the same stream ID on different connections is not merged.

## Reproducibility

The GitHub Actions workflow pins:

- Open5GS `v2.8.0`;
- UERANSIM `v3.3.0`;
- `herlesupreeth/docker_open5gs` lab/configuration commit `cfac9223bf3a1d10ea5faf31773a7defbd0c6b8f`;
- NumPy `2.2.6` and scikit-learn `1.7.2`.

The workflow builds Open5GS and UERANSIM from those source tags, starts a 5G SA core, provisions one UE, starts UERANSIM gNB/UE, captures cleartext HTTP/2 SBI traffic involving the AMF, and decodes CreateSMContext request/response attempts from the PCAP. Mid-run SCP restart forces a fresh observed AMF–SCP HTTP/2 connection epoch. An unsupported-DNN episode is attempted, but its status is measured rather than assumed.

## Trust/evidence split used in CI

GitHub-hosted CI cannot provide a physically independent trusted appliance. The experiment therefore emulates the trust split: the NF/self-report branch and the witness/verification branch are separate processes and artifacts, but they share one hosted runner. The PCAP is treated as the independent witness input for algorithm evaluation. This is suitable for reproducibility and correctness testing, not for claiming physical compromise resistance of the host.

The SBI witness is captured by exactly one tcpdump process started before the 5GC so the AMF-side HTTP/2/HPACK state is present from connection establishment; competing writers to the evidence file are forbidden.

Network-derived events are never silently replaced with synthetic data. If no CreateSMContext attempts can be decoded, the job fails. Controlled scenarios that Open5GS does not reliably generate on demand (overload/error/redirect transformations, bounded witness loss, coordinated false self-reports, replay, scope substitution, and witness compromise) bootstrap outcomes from the captured CreateSMContext profile and then apply explicit transformations. They are clearly labelled controlled extensions and are not presented as naturally occurring Open5GS failures.

## Comparisons implemented

The analysis compares:

1. hierarchical ML without report-consistency verification;
2. naive missing-as-failure scalar comparison;
3. correct scalar interval comparison;
4. exact centralized feasible-set verification;
5. exact hierarchical verification using joint feasible relations;
6. coordinate-wise intervals, which can lose dependencies;
7. equal-budget disclosure policies: uniform, random, ML-only, and the proposed mandatory-audit + `(epsilon + anomaly_rank) * ambiguity_reduction / cost` policy.

The deterministic verifier runs independently of ML. Isolation Forest only ranks extra evidence requests. Random Forest is intentionally not trained from synthetic labels generated by the same rule under evaluation.

## Scenarios

The closed-loop analysis covers honest normal service, honest overload, ordinary errors/retries/redirect abstractions, inflated success, hidden errors, scope substitution, replayed KIE, observation loss, epoch change, colluding false NF reports with an independent witness, and a witness-compromised scenario explicitly marked as outside the trust model.

For each budget step, evidence is revealed and the feasible set is recomputed before the next query. This avoids evaluating an adaptive scheduler against a fixed pre-revealed dataset.

## Outputs

Artifacts include the raw PCAP, decoded network events, Open5GS/UERANSIM logs, Docker resource snapshots, detector/policy trial CSVs, confidence intervals, JSON summaries, and `report.md`. The report separates measurements taken from the real Open5GS/UERANSIM run from controlled semantic scenarios.

## Guardrails

A successful UE registration or ping is only a smoke test and is not treated as proof of the method. `NOT_REFUTED` means compatible with current evidence, not verified honest. Timeouts are not converted into proofs of an empty feasible set. The workflow uses one CI topology and one pinned version pair, so a passing run is not sufficient to claim general superiority across production 5G cores.
